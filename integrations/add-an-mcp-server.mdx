Alfera ships with thousands of integrations. When the tool you need is not one of them — because it is new, or because your own team runs it — you can connect it yourself, as long as it speaks the Model Context Protocol.

You paste an address. Alfera asks the server what it can do, and each of its tools becomes available to your workers alongside Gmail, Slack, and everything else.

<Note>
  Adding a server is a workspace admin action. Any member can use its tools once an admin turns them on for a worker.
</Note>

## Before you start

You need the server's address. It usually ends in `/mcp`, for example `https://mcp.linear.app/mcp`. Vendors publish it in their own documentation, normally under a heading like **MCP server** or **Remote MCP**.

Two addresses will not work:

- Anything that does not start with `https`.
- Anything running on your own machine, such as `http://localhost:3000/mcp`. Alfera runs in the cloud and cannot reach your laptop. Put the server on a host with a public address first.

## Add the server

<Steps>
  <Step title="Open Integrations">
    In the Alfera app, click **Integrations** in the sidebar menu.
  </Step>
  <Step title="Choose MCP server">
    Under **Connect anything**, click **MCP server**.
  </Step>
  <Step title="Paste the address">
    Enter the server's URL and click **Add server**. Alfera contacts the server while you wait, and saves nothing until it answers.
  </Step>
  <Step title="Finish however the server asks">
    Servers authenticate in three different ways. Each one is covered below.
  </Step>
</Steps>

## The three answers

### The server is ready

Open servers need no credential. Alfera reads their tool list straight away and tells you how many tools it added.

Click **Done**. The tools are in your workspace. Turn them on for a worker to use them.

### The server wants you to sign in

Most hosted servers — Linear, Notion, Sentry, Asana, Stripe — authenticate with your own account there. Alfera works out how, registers itself with the vendor, and gives you a link.

Click **Sign in**. The vendor's own consent screen opens in a new tab, showing Alfera as the application requesting access. Approve it there.

You type your password on the vendor's site, never in Alfera. When you return, the dialog closes on its own and the server's tools appear.

### The server uses a token

Servers your own team runs usually authenticate with a token you generate yourself. In the dialog, click **My server uses a token** and paste it.

Alfera checks the token against the server before saving anything, so a wrong or expired token is refused while you are still looking at the dialog, rather than discovered later as tools that quietly fail. Once accepted, the token is encrypted and stored the same way every other credential is.

<Warning>
  Never paste a token into a chat message. Anything typed in chat stays in the conversation and in the worker's context. Tokens belong in this field, which is a password input.
</Warning>

## Add a server by asking

You can also ask a worker to do it, in chat or in Slack:

```text
Connect the MCP server at https://mcp.deepwiki.com/mcp
```

The worker adds the server and replies with a sign-in link if the server needs one. This is the same action as the dialog, and it needs the same admin permission — asking a worker is not a way around it.

A server that needs a token is the one case a worker declines, and it points you back to **Integrations**. That is deliberate: the token would otherwise be written into the conversation.

## Turn the tools on for a worker

Adding a server gives its tools to nobody. Every worker starts with nothing enabled.

Open the worker, go to its tools, search for the server by name, and enable the ones it should have. Give each worker the tools its job needs and no more.

## What Alfera does with a server you add

A server you paste is not one Alfera has vetted. Several things follow from that.

**Tool descriptions come from the server and are stored word for word.** Your worker reads them, so a dishonest server can put instructions in front of it. Alfera does not rewrite them, because rewriting would misrepresent what the tool accepts.

**A server's own safety claims are not believed.** The protocol lets a server mark a tool as read-only. A dishonest server sets that flag as easily as an honest one, so Alfera ignores it and treats every tool from a server you added as one that changes something.

**Tools that disappear are retired, not deleted.** When a server drops a tool, its record stays so your history still points at it. When a server is unreachable, nothing changes at all — an outage is not evidence that a tool is gone.

**Addresses are checked before they are fetched.** Alfera resolves the hostname, refuses private and internal addresses, and refuses to follow redirects, so an address cannot be used to reach anything inside Alfera's network.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Alfera cannot reach the server">
    Open the address in a browser. Pasting a documentation page is the most common mistake — the address you want is the server itself, usually ending in `/mcp`, and it does not render as a readable page.

    Check that the address starts with `https` and is not running on your own machine.
  </Accordion>

  <Accordion title="Sign-in fails after the consent screen">
    Some servers require a specific plan, or an administrator to enable access, before they issue a token. Check the vendor's requirements for their MCP server.

    If the message names a scope, the server is refusing a permission it advertises. Send the exact message to the vendor.
  </Accordion>

  <Accordion title="The server needs a client ID">
    A small number of servers, GitHub among them, do not let applications register themselves and need credentials arranged in advance. Contact us and we will configure it.
  </Accordion>

  <Accordion title="The server is added but a worker will not use its tools">
    Tools are off by default for every worker. Open the worker's tools, search for the server, and enable what it needs.
  </Accordion>

  <Accordion title="Alfera says the server is already in this workspace">
    It is connected already. Find it in **Integrations** under the vendor's name, such as Linear, rather than the address you pasted.
  </Accordion>
</AccordionGroup>
